# /wrapup Development Journal

개발 과정의 의사결정, 시행착오, 설계 변경의 맥락을 기록하는 저널.
CHANGELOG는 "무엇이 바뀌었는가"를, 이 저널은 "왜, 어떤 과정을 거쳐 바뀌었는가"를 기록한다.

## 2026-03-09 — v1.5.0: 후속 작업 추천 이관 + 스텝 재구성

### 배경

글로벌 CLAUDE.md에 "태스크 완료 후 연계 제안" 규칙이 있었다. 매 세션의 태스크 완료 후 3개 연계 작업을 추천하는 기능인데, 두 가지 문제가 있었다:

1. **컨텍스트 점유**: 모든 세션에서 항상 로딩되는 글로벌 규칙이라 메모리를 상시 차지
2. **발동 타이밍 불확실**: "하나의 완결된 태스크를 마무리한 후"라는 조건이 동적이라 일관성이 떨어짐

### 결정

wrapup 스킬로 이관. 세션 종료 시에만 발동하므로 컨텍스트 효율적이고, todo 등록과 자연스럽게 연결된다.

### 스텝 순서 재구성 — 핵심 논리

기존 흐름에서 /todo 연동(Step 8)이 세션 평가(Step 5) 뒤에 있었다. 이 순서에서는 "얼마나 좋은 후속 작업을 발굴했는가"가 평가 대상에서 빠진다.

변경: todo 연동 + 후속 추천을 세션 평가 앞(새 Step 5)으로 이동. 세션 평가의 `learning_value` 메트릭이 후속 작업 발굴 품질까지 포함하게 된다.

```
Before: ... → Step 4 수정 → Step 5 평가 → Step 6 저장 → Step 7 Memory → Step 8 /todo → Step 9 완료
After:  ... → Step 4 수정 → Step 5 추천+/todo → Step 6 평가 → Step 7 저장 → Step 8 Memory → Step 9 완료
```

### 드래프트 통합

후속 추천은 드래프트의 새 섹션(`◇ 다음에 이어볼 만한 작업`)으로 Step 3에서 표시된다. 사용자가 드래프트 전체를 리뷰할 때 추천도 함께 확인하고, 수정 루프(Step 4)에서 추천 내용도 수정 가능.

## 2026-03-02 — v1.4.0: 세션 평가 기능 추가

### 배경

세션 요약과 Lesson-Learned는 "무엇을 했고 무엇을 배웠는가"를 기록하지만, "세션이 얼마나 잘 운영되었는가"에 대한 메타-피드백이 없었다. 같은 실수(예: 코드 검증 생략)가 반복되는데 이를 추적할 수단이 없었다.

### 핵심 설계 결정

- **AI 먼저, 사용자 나중**: anchoring bias 방지. AI가 솔직한 자기 진단을 먼저 제시하면 사용자가 교정 가능
- **overall_score 없음**: 5개 서브 메트릭이 곧 평가. 단일 점수로 압축하면 정보 손실
- **improvement tag**: kebab-case 태그로 반복 탐지 가능. 향후 졸업 시스템(v1.5.1)의 매칭 키

### 시행착오

- AskUserQuestion의 옵션 4개 제한으로 5점 척도 표현 불가 → 텍스트 기반 번호 입력으로 전환
- AskUserQuestion의 "Other" 선택 시 텍스트 필드 포커스 이동 불가 → 텍스트 피드백도 텍스트 기반으로 변경
- 결국 v1.4.4에서 AskUserQuestion의 questions 배열 일괄 방식으로 3개 피드백 질문을 한 번에 표시하는 방식으로 안정화

## 2026-03-01 — v1.3.0: Auto Memory 연동

### 배경

Claude Code의 auto memory 기능이 세션 중 사실(fact)을 자동 기록하는데, wrapup의 Lesson-Learned와 내용이 겹칠 수 있었다. 같은 정보가 두 곳에 기록되면 관리 부담.

### 해결 방식

- **중복 탐지**: 드래프트 생성 전 auto memory 스캔 → 겹치는 lesson에 `[📝 auto memory]` 태그
- **역할 분리**: auto memory = 사실(fact), lesson = 맥락/발견과정(context)
- **양방향 동기화**: 저장 후 auto memory에 없는 AI lesson을 승격 제안

### memory_ref 필드

lesson 스키마에 `memory_ref` 필드 추가. auto memory 파일 참조를 추적하여 나중에 "이 lesson의 원본 사실은 어디에 있는가?"를 찾을 수 있게 함.

## 2026-02-24 — v1.1.0~1.2.x: 안정화 기간

### 주요 시행착오

1. **bash 안전 검사 문제**: `python -c "..."` 안에 `$()` 텍스트가 있으면 Claude Code가 command injection으로 판단. Write 도구 + `--file` 인수 패턴으로 해결.

2. **Windows cp949 인코딩**: Python stdout이 cp949일 때 `json.dumps(ensure_ascii=False)` 한글 출력이 `?????`로 깨짐. UTF-8 stdout 강제 패치로 해결.

3. **CJK 테이블 정렬**: 한글(double-width)과 영문(single-width) 혼용 시 좌우 세로선 정렬이 어긋남. 가로선 전용 레이아웃으로 전환.

4. **드래프트 포맷 반복 실패**: 화살표(`▶`), 들여쓰기 0칸 등의 포맷 오류가 반복 발생. 자가 검증 규칙과 ❌ 틀린 예를 SKILL.md에 명시하여 해결.

### 교훈

- 멀티라인 데이터를 bash에 전달하는 건 항상 위험하다 → Write 도구로 파일 저장 후 경로만 전달하는 패턴이 안전
- 한/영 혼용 터미널 UI는 세로 정렬을 포기하고 가로선 구분으로 가야 한다
- AI에게 포맷 규칙을 지키게 하려면 "올바른 예"만으로는 부족하고, "틀린 예 + 금지" 명시가 필수

## 2026-02-23 — v1.0.0: 초기 설계

### 원래 동기

Claude Code 세션에서 배운 것들이 휘발되는 문제. 특히:
- 사용자가 배운 것 vs AI가 배운 것의 관점 차이가 기록되지 않음
- 결정사항의 근거(rationale)가 유실됨
- 세션 간 학습의 연속성이 없음

### 초기 설계 결정

자세한 내용은 `docs/plans/2026-02-23-wrapup-skill-design.md` 및 `docs/research/research-report-2026-02-23-lesson-learned-system-design.md` 참조.

- **JSONL 포맷**: git 친화적, 증분 기록, 단일 파일로 관리 용이
- **2계층 구조**: 세션 요약(프로젝트 관리) + Lesson-Learned(지적 성장)
- **학습 관점 분리**: 사용자 파일과 AI 파일을 물리적으로 분리
